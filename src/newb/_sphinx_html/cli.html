CLI reference

Rendered from the live Click group via sphinx-click — this tree cannot drift from newb --help-recursive.

newb <target> is the canonical, verb-less invocation (pytest-style); the subcommands below are introspection / maintainer plumbing.

newb

A fresh AI agent tries to use your package — pytest-style.

Example:
$ newb . # current project
$ newb https://github.com/user/repo.git # git URL — shallow-clones
$ newb . –template cli-tool –json
$ newb templates list # introspect
$ newb mcp start # MCP server (stdio)

SOURCE may be a local directory or a git URL (https://, git@, *.git). A sandboxed container session reads your project (respecting .gitignore) and answers the questions in the chosen template. Runtime defaults to docker; auth via NEWB_ANTHROPIC_API_KEY.

Usage

newb [OPTIONS] [SOURCE] COMMAND [ARGS]...

Options

--model <model>

Claude model id.

--runs <runs>

Runs per prompt.

--template <template>

Question template — which prompt set to send the agent.

Options:

cli-tool | python-package

--format <out_format>

Output format.

Options:

json | markdown

--json

Alias for –format json (universal SciTeX flag).

--markdown

Alias for –format markdown.

--runtime <runtime>

Container runtime. docker (default), podman (rootless), or apptainer (HPC).

Options:

docker | podman | apptainer

--scope <scope>

Agent scope. ‘all’ (default): full agentic permissions — agent can install/run/test the package. ‘docs’: read-only audit mode — Read/Glob/Grep only, no Bash/Write/Edit.

Options:

all | docs

--install-mode <install_mode>

How the agent installs the package for post_install_check. ‘editable’ (default): pip install -e . (dev loop). ‘wheel’: build a wheel and install it (release sanity). ‘pypi’: pip install <pkg-name> from PyPI (real-user reproduction).

Options:

editable | wheel | pypi

--harden-memory <SIZE>

Container memory cap, e.g. 2g. Default: unlimited (agent runs free).

--harden-cpus <N>

Container CPU cap (cores). Default: unlimited.

--harden-pids-limit <N>

Container PID cap. Default: unlimited.

--harden-no-network, --harden-network

–harden-no-network adds –network=none (breaks pip + SDK; only for fully offline workflows). Default: bridge.

--harden-tmpfs-noexec, --no-harden-tmpfs-noexec

Mount /tmp with noexec,nosuid. Default: off (pip/pytest sometimes write+exec wheels in /tmp).

--pip-cache <PATH>

Mount a host pip cache into the container at ~/.cache/pip. Speeds up local-dev iteration on repeated runs. Leave unset for CI (cold install is the honest newbie test). Falls back to NEWB_PIP_CACHE_DIR.

-v, --verbose

Verbosity: -v echoes the resolved config + total wall time; -vv also streams container stderr in real time (per-prompt timing + SDK chatter); -vvv adds the raw container argv.

--help-recursive

Flatten help for every subcommand.

-V, --version

Show the version and exit.

Arguments

SOURCE

Optional argument

newb (v0.26.7) — A fresh AI agent tries to use your package — pytest-style. Run newb <SOURCE> against any project directory or git URL.

dev

Developer / maintainer plumbing (CI secrets, repo bootstrap).

Usage

newb [SOURCE] dev [OPTIONS] COMMAND [ARGS]...

install

Install newb CI on TARGET = scaffold-workflow + set-secret.

Example:
$ export NEWB_ANTHROPIC_API_KEY=sk-ant-…
$ newb dev install owner/repo # PR + secret
$ newb dev install owner/repo –push # direct-push + secret
$ newb dev install . –no-secret # workflow only
$ newb dev install owner/repo –dry-run # preview

TARGET = <owner>/<repo>; ‘.’ or omitted = current git remote. An auth source (NEWB_ANTHROPIC_API_KEY, NEWB_CLAUDE_CODE_CREDENTIALS_JSON, or ~/.claude/.credentials.json) is required unless –no-secret.

Usage

newb [SOURCE] dev install [OPTIONS] [TARGET]

Options

--push

Direct-push the workflow instead of opening a PR.

--force

Overwrite an existing secret AND workflow.

--no-secret

Skip the secret step (e.g. if an org-level secret is already in scope).

--dry-run

Print what would happen without making any remote changes.

-y, --yes

Skip the interactive confirmation prompt.

Arguments

TARGET

Optional argument

scaffold-workflow

Drop .github/workflows/newb.yml into TARGET.

Example:
$ newb dev scaffold-workflow owner/repo # open a PR
$ newb dev scaffold-workflow owner/repo –push # direct-push
$ newb dev scaffold-workflow . # current git remote
$ newb dev scaffold-workflow owner/repo –dry-run # preview only

TARGET = <owner>/<repo>; ‘.’ or omitted = current git remote.

Usage

newb [SOURCE] dev scaffold-workflow [OPTIONS] [TARGET]

Options

--push

Direct-push to default branch instead of opening a PR.

--force

Overwrite an existing newb.yml workflow.

--dry-run

Print what would happen without making any remote changes.

-y, --yes

Skip the interactive confirmation prompt.

Arguments

TARGET

Optional argument

set-secret

Set the newb auth secret on TARGET.

Example:
# API-key path (per-token billing)
$ export NEWB_ANTHROPIC_API_KEY=sk-ant-api03-…
$ newb dev set-secret owner/repo

# OAuth flat-rate path (Claude Code Pro / Max). Auto-detected # from ~/.claude/.credentials.json or NEWB_CLAUDE_CODE_CREDENTIALS_JSON. $ newb dev set-secret owner/repo

TARGET = <owner>/<repo>; ‘.’ or omitted = current git remote. Picks NEWB_CLAUDE_CODE_CREDENTIALS_JSON if either the env var or ~/.claude/.credentials.json is available; otherwise falls back to NEWB_ANTHROPIC_API_KEY from the host env.

Usage

newb [SOURCE] dev set-secret [OPTIONS] [TARGET]

Options

--force

Overwrite an existing secret.

Arguments

TARGET

Optional argument

gate

Evaluate a newb JSON report against [tool.newb.gate] criteria.

Example:
$ newb . –format json > report.json
$ newb gate report.json # exits 0 (pass) or 1 (fail)
$ newb . –format json | newb gate - # via stdin

Pass ‘-’ as REPORT_PATH to read from stdin.

Usage

newb [SOURCE] gate [OPTIONS] REPORT_PATH

Options

--pyproject <pyproject_dir>

Directory to search upward from for pyproject.toml.

Default:

'.'

Arguments

REPORT_PATH

Required argument

install-shell-completion

Install shell completion for SHELL.

Example:
$ newb install-shell-completion bash
$ newb install-shell-completion # auto-detect
$ newb install-shell-completion zsh –dry-run

Appends an eval line (bash/zsh) or writes a completion file (fish). Idempotent — re-runs are no-ops.

Usage

newb [SOURCE] install-shell-completion [OPTIONS] [[bash|zsh|fish]]

Options

--rc-path <rc_path>

Override the rc / completion file (default depends on shell).

--dry-run

Print what would be written without modifying any file.

-y, --yes

Skip the interactive confirmation prompt.

Arguments

SHELL

Optional argument

list-python-apis

List newb’s public Python API surface (callables in import newb).

Example:
$ newb list-python-apis
$ newb list-python-apis –json

Usage

newb [SOURCE] list-python-apis [OPTIONS]

Options

--json

Machine-readable JSON output.

mcp

newb [SOURCE] mcp [OPTIONS] COMMAND [ARGS]...

list-tools

List MCP tools exposed by newb’s server.

Example:
$ newb mcp list-tools
$ newb mcp list-tools –json

Usage

newb [SOURCE] mcp list-tools [OPTIONS]

Options

--json

Machine-readable JSON output.

start

Start the newb MCP server (stdio transport).

Example:
$ newb mcp start
$ newb mcp start –dry-run

Usage

newb [SOURCE] mcp start [OPTIONS]

Options

--dry-run

Print the planned action and exit (don’t bind / serve).

-y, --yes

Bypass any TTY confirm (no-op here; present for SciTeX CLI parity).

print-shell-completion

Print the shell-completion script for SHELL to stdout.

Example:
$ newb print-shell-completion bash
$ newb print-shell-completion zsh > ~/.zsh-newb-completion
$ newb print-shell-completion # auto-detect from $SHELL

SHELL is one of: bash, zsh, fish. Auto-detected when omitted.

Usage

newb [SOURCE] print-shell-completion [OPTIONS] [[bash|zsh|fish]]

Arguments

SHELL

Optional argument

show-env-template

Emit a copy-pasteable NEWB_* env-var template.

Example:
$ newb show-env-template # to stdout
$ newb show-env-template -o ~/.config/newb/local.src # to file
$ newb show-env-template –json # JSON schema

Usage

newb [SOURCE] show-env-template [OPTIONS]

Options

-o, --output <output>

Write to a file instead of stdout.

--json

Machine-readable JSON (env-var schema) instead of the .src template.

skills

newb’s own agent-facing skill leaves (under src/newb/_skills/newb/).

Usage

newb [SOURCE] skills [OPTIONS] COMMAND [ARGS]...

get

Print one skill leaf’s content (e.g. newb skills get SKILL.md).

Example:
$ newb skills get SKILL.md
$ newb skills get 04_isolation
$ newb skills get 01_quick-start –json

Usage

newb [SOURCE] skills get [OPTIONS] NAME

Options

--json

Machine-readable JSON output (path + content fields).

Arguments

NAME

Required argument

install

Copy newb’s skill leaves into TARGET (default ~/.claude/skills/newb/).

Example:
$ newb skills install # ~/.claude/skills/newb/
$ newb skills install –target /tmp/foo # custom location
$ newb skills install –dry-run # preview only

Usage

newb [SOURCE] skills install [OPTIONS]

Options

--target <target_dir>

Where to copy newb’s skill leaves into.

Default:

'~/.claude/skills'

--force

Overwrite existing files at the target.

--dry-run

Print what would be copied without writing.

-y, --yes

Skip the interactive confirmation prompt.

list

List newb’s skill leaves (SKILL.md + NN_*.md sub-skills).

Example:
$ newb skills list
$ newb skills list –json

Usage

newb [SOURCE] skills list [OPTIONS]

Options

--json

Machine-readable JSON output.
